一笔项目款，两只时钟。

确认日回答“这笔收支发生了吗”；收付日回答“现金真的进出了吗”。用应收、应付和设备付款，把两边接起来。

面向服务项目的简化规划，不是完整财务报表。
01 / 确定观察窗口

给每笔钱一个日期

观察1–90天；延迟0–60天，仅后移已定收入回款日。期初现金0–10亿元。
02 / 填写期间事项
类型：收入 / 费用 / 设备 / 注资
日期填第几天（1–90），未定收付日填 - 。设备、注资两日相同。收入/费用不支持预收预付。单笔最多1000万元、两位小数，最多100笔；支持制表符。

保存与迁移

有效条件自动保存在本机。无服务器上传。
03 / 先看能否付得出

导出这次规划

CSV含第0天及全部观察日；MD含条件和事项；PNG为期末摘要。精确条件用JSON恢复。

使用边界

  1. 确认收支差额 = 已确认服务收入 − 已确认期间费用。设备现金支出与注资不计入，不含折旧、税费、利息等；不能当作法定净利润。
  2. 期初应收、应付为零；不支持预收预付、分次收付、退款、存货成本、借款偿还。类型和确认时点由你核对。
  3. 现金按日末净额计算，同日先付后收的临时缺口不会体现。负数是计划缺口，不代表账户可以透支。
  4. 延迟只是情景假设，不预测客户行为。观察窗外的回款仍列应收，不算已到账。示例为虚构服务项目。
